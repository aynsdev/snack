Snack (internal team communication platform, Laravel 13 + React 19 + Inertia v3 + Reverb) is being built in 7 phases, one at a time. The user explicitly forbids generating the whole app in one pass.

- **Phase 1 — Foundation** (workspaces, membership, roles, channel CRUD, sidebar nav): complete, verified.
- **Phase 2 — Channels & Messaging** (send/edit/delete, cursor-paginated history, composer, unread pointers, real-time broadcast, notification sound via `public/snack.mp3`): complete, verified in-browser 2026-07-29. Committed.
- **Phase 3 — Direct Messages**: complete, verified in-browser 2026-07-30. Direct **and** group conversations, add-people / rename / leave, mute + notification level, DM unread badges, presence in the header. Conversations are addressed by an opaque ULID `public_id` — see [[snack-conversation-public-id]]. Not committed.
- **Phase 4 — Collaboration**: complete 2026-07-31, gate green (Pint, PHPStan level 7, **359 Pest**, **196 Vitest**, ESLint, Prettier, tsc, Vite build). Committed by the user as `889d8f2` (84 files, +8,661). **Browser-verified end to end on 2026-07-31** — threads, reactions, mentions, pins, saves, and the three new views all confirmed against the database, not just the UI. Three bugs found during verification and fixed **after** that commit, so they are uncommitted at time of writing: the reaction picker being clipped ([[snack-overlay-clipping]]), Threads/Mentions/Saved wearing the wrong sidebar, and the thread panel's reply tally not moving. All five pieces shipped: threads, reactions, mentions, typing indicators, saved/pinned. See [[snack-phase-4-decisions]] for the design calls, and [[snack-react-effect-identity]] for the one real bug found afterwards — the `@`-picker fetching in a loop.
- **Phase 5 — Files & Search**: complete 2026-07-31, and **browser-verified end to end the same day** against the database, not just the UI — upload with progress, files-only send, queued thumbnail, Files browser, `has:file` search with a highlighted snippet, and avatar upload all confirmed. Gate green (Pint, PHPStan level 7, **457 Pest**, **217 Vitest**, ESLint, Prettier, tsc, Vite build). Committed by the user as `cf8c95b` (70 files, +6,828). Needed no migration: Phase 1 had already laid down `message_attachments`, `messages.search_vector` + its GIN index, and `users.avatar_path`. Also shipped: attachment upload/delete endpoints, `snack:prune-uploads` and `snack:reindex-messages` (both scheduled in `routes/console.php`), a Files browser, a search page with `from:`/`in:`/`has:file`/`before:`/`after:`, ⌘K, and profile-picture upload. See [[snack-phase-5-decisions]].
- **Phase 6 — Notifications & Administration**: complete 2026-07-31, **browser-verified end to end the same day** against the database — mention → queued fan-out → live arrival with no reload → badge → mark read; preferences saved; workspace settings with both audit actions recorded separately; audit viewer with a working subject filter; channel rename propagating through URL, header, sidebar, and composer. Gate green (Pint, PHPStan level 7, **541 Pest**, **225 Vitest**, ESLint, tsc). Committed by the user as `0fa1ddb` (70 files, +6,894). Shipped: notification centre + preferences + email/digest (`snack:send-digests`, scheduled hourly), workspace settings + logo, audit viewer, channel settings (edit + archive/restore). All **17** `AuditAction` cases are now wired — the 7 dead ones are gone.
  - **Needed no migration.** `channel_members.notification_level`, `workspace_members.notification_preferences`, the `notifications` table + its unread partial index, and `audit_logs` were all already there from Phase 1. The brief's premise that channels lacked a notification level was wrong; what was missing was the write path and the UI. Check the schema before believing a phase needs a migration — and before believing it does not (Phase 4 did).
  - Two real bugs surfaced: an app-wide Postgres timezone skew ([[snack-postgres-timezone]]) and `ChannelPolicy::archive` delegating to `update`, which made restoring an archived channel impossible. See [[snack-phase-6-decisions]].
- **Onboarding & marketing** (out of phase, 2026-07-31, after Phase 6): first-run setup wizard at `/setup`, a real Snack landing page replacing the stock Laravel starter welcome, and the auth shell rebranded. Gate green (**559 Pest**, **225 Vitest**, Pint, PHPStan 7, tsc, ESLint, Prettier, build); landing page browser-verified in light and dark, `/setup` confirmed 404 on the initialized dev instance. Registration stayed invite-only because it **already was** — see [[snack-first-run-setup]] for why a fresh install was a dead end until this existed.
- **Phase 7 — Optimization**: complete 2026-08-01, **browser-verified against a 400-message channel** seeded and then deleted (dev data restored). The timeline is genuinely windowed now — 20 rows in the DOM instead of 400 — with prepend drift measured at **0px** and send-follow landing exactly at the bottom. Gate green (**568 Pest**, **229 Vitest**, Pint, PHPStan 7, tsc, ESLint, Prettier, build). Shipped: `@tanstack/react-virtual` windowing, `app/Services/MessageContainers.php`, and `tests/Feature/Performance/QueryCountTest.php`. **Uncommitted at time of writing.**
  - Found two real N+1s (Mentions and Saved, 201 → 23 queries) and, in the same code, a **live permissions bug** — an eager-load column subset omitted the flags `ChannelPolicy` decides on, and unselected columns read back as null rather than raising.
  - **Bundle splitting was attempted and reverted.** It measured 219 → 116 KB gz but blanked `/login`. Do not redo it without reading [[snack-phase-7-decisions]] first.
  - All 7 phases are now done. There was no Phase 8; work after this point is the user's call, and **Projects below is the first of it**.
- **Projects — Jira-style boards** (out of phase, 2026-08-05, asked for by the user with a Jira screenshot as reference): boards, sprints, backlog, customizable cards, and assignment scoped to project members. The rail's "Tasks — coming soon" placeholder is now the Projects section, and the sidebar takes a project-list shape inside it (the same switch DMs make). Gate green (**789 Pest**, **372 Vitest**, Pint, tsc with zero errors, ESLint, build). **Browser-verified end to end on snack.test** — project created, sprint planned and started, cards filed as PWA-1/2/3, drag between columns, assignment to a project member, label applied, and a sprint completed with the unfinished work carried back to the backlog *keeping its column*. Demo project deleted afterwards; dev data restored. **Uncommitted at time of writing.**
  - Needed six new migrations: `projects`, `project_members`, `board_columns`, `sprints`, `tasks`, `task_labels` + its pivot. Nothing existing covered any of it.
  - One bug found in the browser and fixed: the new `task_assigned` notification rendered "Unknown" as its source, because `ContainerLabel` has nothing to name for a row that is not about a message.
  - Task **comments were deliberately left out** — not in the scope the user named, and whether a card's discussion is its own container or a channel thread is a real decision rather than an afterthought.
  - See [[snack-projects-decisions]] for the design calls, especially the two-axis card placement that the sprint rollover depends on.

**Schema note:** Phase 1 laid down nearly all of Phase 4's tables (`message_reactions`, `mentions`, `saved_messages`, `pinned_messages`, plus `messages.parent_message_id`). The one genuine gap was thread read state, which needed a new migration in Phase 4: `thread_subscriptions` plus a `messages.last_reply_id` pointer. Do not assume the remaining phases need no migrations.

See [[snack-spec-constraints]], [[snack-local-serving]], and [[snack-container-abstraction]].
